Before you begin

  1. Open both starters. Download or clone the linked repos into separate folders. Each README covers Windows setup, synthetic data, the exact contract and test commands. Keep the two codebases separate.
  2. Prepare your tools. Use the specified Node.js version. For Cursor installation and the unassessed practice, follow the beginner setup guide. Arrange account/model access privately with the coordinator; do not assume you need to buy a subscription.

Project 01 · Diagnose and repair

Recover a failing data import

Repair an inherited importer so retries, repeated records and interrupted runs do not lose or duplicate data. Failed runs must report failure, not false success or endless retries.

github.com/atten-x/atten-x-recovery-work-sampleAny editor. AI assistance is welcome.
  1. Diagnose with evidence. Reproduce a failure, test an explanation and record what changes your understanding. Send brief checkpoints around two and four working hours: actual result, current hypothesis, next step and any blocker. Submit early if finished.
  2. Repair, then challenge it. Make a focused change and run every supplied scenario. Add regression tests; check exact stored records, restart behavior and truthful failure states.
  3. Leave a reproducible result. Keep a short trail of hypothesis → experiment → result → next decision. Identify any remaining failures and the next useful test.

Project 02 · Direct and verify

Lead a phased build in Cursor

Add lead-status editing and filtering to the starter app. Changes must survive reload and restart; invalid updates and failed saves must not appear successful.

github.com/atten-x/atten-x-cursor-work-sampleCursor required. Prior Cursor experience is not assumed.
  1. Plan and configure. Before implementation, submit a Cursor-assisted phase plan with scope, dependencies and QA criteria. Configure coordinator, builder and fresh-context reviewer roles using the supplied references. You choose the phases and supported models; sequential agents are fine.
  2. Run the phase loop. Direct AI through build → independent QA → repair/retest → validation. Save commands, results and approval decisions. Do not advance with unresolved failures. Inspect the changes yourself and explain direct edits or interventions.
  3. Prove the checks work. Test the actual user flow. Define one additional case and expected result before asking AI to write its test. Deliberately break a behavior, demonstrate the test fails for that defect, then restore and rerun.

Working rules for both projects

  • Verify, don’t just accept. An agent’s success message is not evidence. Preserve the supplied data rules, protected fixtures and acceptance checks; report a genuine harness defect instead of weakening the test.
  • Ask useful questions. Clarification and focused hints are welcome. No forced disagreement with AI, invented setbacks or minimum number of failed attempts is required. Sound partial progress is better than an unsupported completion claim.
  • Keep the work local and safe. Use only the supplied synthetic data. No production access, client data, live integrations or deployment. Never include credentials or private account details in code or AI excerpts.

One private handoff

Send one ZIP file via email with both assignment project folders within. The ZIP should include:

  • Both projects’ source and tests in clearly named folders, with reproducible run instructions. Exclude dependencies, local databases and build output.
  • One concise work log with a section per project: time spent, key decisions, AI/help used, actual check results and remaining gaps. Existing note templates are optional formatting aids; do not duplicate the same notes.
  • The Cursor workflow evidence: active configuration and invocation instructions, phase plans, QA/fix decisions, the break/restore test result and representative sanitized agent handoffs. No full chat dumps.

The starter repos are public. Do not submit solutions or personal notes through public issues, branches or pull requests.

Live follow-up

Reserve 45 minutes within each project’s budget for review with us.

For recovery, investigate a new combination of the documented failure conditions. If your repair already handles it, demonstrate why.

For Cursor, scope a small extension, direct the agents, inspect the result and run a meaningful check.

We are looking for evidence-led decisions and verified progress, not speaking speed or completion at any cost.
